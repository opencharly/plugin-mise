# 2026.321.2143 — feat(mise)!: implement the builder's deploy-time ops — collect-context and reverse

## Summary

`builder:mise` declared itself to the host but implemented only `OpResolve`. The host asks **every**
builder for the deploy-time legs too, so any bed deploying a mise-composed image died with:

```
builder "mise" collect-context: InvokeProvider builder:mise op=collect-context:
  rpc error: code = Unknown desc = mise: unsupported op
```

Head `f7e6904`, **3 files, 70 insertions(+), 1 deletion(-)**.

| change | file |
|---|---|
| `case sdk.OpCollectContext` and `case sdk.OpReverse` added to the `Invoke` dispatch, and the "unsupported op" message now names all five served ops | `candy/plugin-mise/provider.go` |
| `invokeCollectContext` and `invokeReverse`, each decoding the host input and dispatching to the **shared** `kit.BuilderCollectContext` / `kit.BuilderReverse` | `candy/plugin-mise/mise_builder.go` |
| `TestInvoke_DispatchesTheDeployTimeBuilderOps` — drives both ops through the real dispatch and fails without them | `candy/plugin-mise/mise_builder_test.go` |

### Why the shared kit, not a local implementation

The four `plugin-builder-*` plugins (aur, cargo, npm, pixi) all implement both legs through
`kit.BuilderCollectContext`/`kit.BuilderReverse`. Dispatching to the same functions means mise's
stage-context keys are the ones the shared render already produces, rather than a second definition
that can drift from it — R2, one canonical implementation per behaviour.

### Blast radius

Not one bed. **Every** mise bed routes through `builder:mise`: alpine, arch, cachyos, omarchy, debian,
fedora and ubuntu — fourteen beds in this repo alone.

## How tested

```
$ charly -C … check run check-mise-ubuntu-2604-pod      # pristine main, cbc038f
```

**And on this branch:**

```
$ charly -C … check run check-mise-ubuntu-2604-pod
PASS (steps=16, skipped_checks=8)
```

The eight skipped checks are the `mise-module-*` probes, which carry a build-context that is not
active in live mode — the same convention the other beds use, and no relation to the changed path.

**Both legs covered, and the coverage provably fails without the change.** A bed can only reach the
collect-context leg in this repo (no `disposable: true` target exercises teardown), so the reverse leg
is covered by a test that drives both ops through the real `Invoke` dispatch:

```
$ git checkout origin/main -- provider.go && go test ./...
--- FAIL: TestInvoke_DispatchesTheDeployTimeBuilderOps
    Invoke("collect-context"): mise: unsupported op "collect-context" (serves only "resolve", …)
FAIL

$ go test ./...          # this branch
ok  github.com/opencharly/plugin-mise/candy/plugin-mise
```

That is the production error reproduced by the test, for both legs.

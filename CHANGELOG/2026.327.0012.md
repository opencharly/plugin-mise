# 2026.327.0012 — chore(deps)!: adopt the sdk that stamps the builder reply output

## Summary

Adopts opencharly/sdk `v0.2026326.2248`, the release that **stamps the builder reply's required `output`** and carries `deploykit.ValidateBuilderResolveReply` on the host side (opencharly/spec#424 made the field required; opencharly/sdk#619 is the host half).

Every `Invoke` in this repo is one call into `sdk.InvokeBuilder`, so the pin bump is the code change — and it is required, not cosmetic: a plugin built against an older sdk answers *without* an `output`, and the host now refuses that reply at its first message, naming the field (opencharly/sdk#615 — the silent "payload copied, package never installed" case).

- `github.com/opencharly/sdk` `v0.2026326.342` → `v0.2026326.2248`
- `github.com/opencharly/spec` `v0.2026326.323` → `v0.2026326.2226`
- **a new test asserts the reply's discriminator on this tree**, not by reference to the sdk: it invokes this plugin's own provider, decodes the answer, and requires `output == "files"`. Against the pre-change sdk it does not compile (no `Output` field, no `kit.BuilderOutput*`); a plugin that stopped routing through `sdk.InvokeBuilder` would answer empty, which is the case the host now refuses.

# 2026.281.0741 — docs(mise): name the venue precondition for a tool archive, with the measured pair (#13)

Agent: `retention` · session `task-12` — cluster **C10a** of `plan/issue-ledger-2026-10-07.md`

## Summary

`plugin-mise#13` is a **missing-guidance** defect with a measurable premise, and this PR lands the
guidance in the three places a reader looks — plus one premise correction that measurement forced.

**The mechanism (unchanged, and the reason guidance is the fix):** a `mise:` step that installs a tool
fetches that tool's archive from the network of the **build venue**, never from the host running
`charly` — and `charly` does not forward host environment variables into an image build. So a venue
that filters the CDN fails the bed *inside the image build* with mise's own error, which reads like a
plugin defect:

```
mise ERROR Failed to install core:go@1.25: HTTP status client error (404 Not Found) for url
  (https://dl.google.com/go/go1.25.14.linux-amd64.tar.gz)
```

**The lever is authored config, not a product change:** a `mise:` step carries an `env:` field, so the
mirror belongs in the step:

```yaml
- check: install go via mise, from a mirror the build venue can reach
  mise:
    command: use
    tool: go@1.25
    env:
      MISE_GO_DOWNLOAD_MIRROR: https://mirrors.aliyun.com/golang
      MISE_GO_SKIP_CHECKSUM: "1"
```

**Where the guidance now lives** (this is what "missing guidance" means — the files that own it):

- `candy/plugin-mise/charly.yml`'s `mise-skill:` **content**, i.e. the source of `/charly-image:mise`
  (the skill an author loads): a new **"Venue precondition"** section with the measured pair and the
  `env:` block.
- `README.md`: the same recipe for users, with the failure text they will see.
- `charly.yml`'s bed-image section: a **comment** naming the precondition for the whole
  `check-mise-<distro>` family. It is a comment and not a candy `description:` deliberately — those
  entities carry two `candy:` keys apiece, and my first attempt at a description edit produced
  `conflicting values` for `check-mise-arch`; a comment cannot collide with a key, and it sits exactly
  where someone reading the bed file looks.

**Premise correction, measured (also posted on the issue, rule 11d).** The filed symptom does **not
reproduce on this venue today**, at the real boundary (inside the build venue, not on the host):

```
$ podman run --rm quay.io/fedora/fedora:43 sh -c 'curl -s -o /dev/null -m 20 -w "%{http_code}\n" <url>'
dl.google.com/go/go1.25.14.linux-amd64.tar.gz          200
mirrors.aliyun.com/golang/go1.25.14.linux-amd64.tar.gz 200
$ podman run --rm ghcr.io/opencharly/fedora-dsh:2026.279.0834 sh -c '... same two ...'
dl.google.com=200   aliyun=200
```

So the CDN is *not* filtered here today (the 404 was measured 2026-10-03). The guidance above is what a
filtered venue needs; on this venue the bed has no precondition problem — which the issue's own
"venue-limited" framing assumed away.

The `curl: not found` line belongs to the **curl-less main stage**, whose step 2 is
`(curl -fsSL "$TASK_URL" || wget -qO- "$TASK_URL") | tar …`: on a bare `alpine:3.24` curl is absent, the
`||` fallback fetches with `wget`, that step succeeds — and its stderr flushed late, so it appears after
the next step's header. I read a handled fallback as a fatal error, and I compounded it by running
`grep -c "BUILD rc"` **while the build was still running** and taking that grep's exit status for the
build's. Verified independently of the log, on the image the stage actually ran in:

```
$ podman run --rm ghcr.io/opencharly/alpine-builder:2026.281.0716 sh -c 'command -v curl; id -u; echo $PATH'
/usr/bin/curl
1000
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

`curl-tar`'s `package: [curl, tar, gzip]` resolves correctly for apk (that image's own step 5/18 is
`apk add --no-cache curl tar gzip`). The false issue is `opencharly/plugin-mise#16`, filed by the Lead
on my evidence and assigned to `bed-venues`: **I commented the correction there and asked for it to be
closed** rather than leave another session chasing a defect that does not exist. Its cost is mine.
